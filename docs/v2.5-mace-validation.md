# v2.5 MACE Validation Checklist — collatz_eea_v2

This is NOT a Cursor build instruction. This is what CB/MACE checks
once Cursor's iOS and Android ports exist, per
docs/collatz-eea-v2-porting-notes.md. See ROADMAP.md's 2026-09-14 and
2026-10-03 v2.5 entries for full background.

1. MACE can observe and correctly annotate the custom `svc #0x10`-
   `#0x15` dispatch — not a standard BSD/Mach or Linux syscall number
   range, a genuinely custom table. Good stress test for whether
   MACE's annotation logic over-assumes "the syscall table" is a
   fixed, known set.
2. Register state at each `svc` call site (x20, x24, x26, x28) reads
   correctly via the MACE context panel on both platforms.
3. The Frida-detection corruption path (x28) reads 0 when MACE itself
   is attached via lldb (not Frida) on both platforms — confirming
   MACE's own dynamic instrumentation doesn't trip Frida-style
   detection the way process-injection tools do.
4. Swift "you are here" annotation resolves correctly at the check
   function's breakpoint on iOS (`EnigmaChecker.check()`) — first
   real (non-trivial) Swift annotation target since LocalAuthChecker.
5. JNI "you are here" annotation resolves correctly at the check
   function's breakpoint on Android (`MainActivity.checkFlag()`) —
   first real (non-trivial) JNI annotation target since the
   2026-10-24 trivial validation. The porting spec's naming
   requirement (uppercase class) matters here specifically: MACE's
   current package/class split heuristic resolves on Java naming
   convention, not a real class-table lookup (see BACKLOG.md's
   2026-10-24 entry for the full mechanism and its known limitation).
   If there's appetite later, a deliberately non-idiomatic lowercase
   class name on a SEPARATE build/variant would be a good secondary
   test of that known failure mode — not the primary target.
6. (secondary demo goal, not a MACE engineering requirement) Walking
   through the dual-accumulator collision weakness live via MACE —
   showing register values confirm the algorithm, then showing a
   second, different input also passes — doubles as a real-world
   lesson about collision-resistant check design under deadline
   pressure, alongside the primary syscall-annotation validation.
